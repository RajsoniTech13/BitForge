ETHEREUM_RPC is the Remote Procedure Call (RPC) URL that allows your wallet to interact with the Ethereum blockchain.

Why Do You Need an RPC URL?
It acts as a gateway for your application to read blockchain data and send transactions.

Since Ethereum is decentralized, you need a node (server) to interact with the network.

Public RPCs exist, but they can be rate-limited or slow.

For Ethereum, an RPC URL is required to send transactions and interact with smart contracts.
For Solana, an RPC URL is needed to fetch blockchain data and submit transactions.


-------------------------------------------------------------------------------------

Solana's private key is not a simple hex string like Ethereum's. Instead, it's a Uint8Array (array of 64 numbers) representing the secret key, while Ethereum uses a 32-byte hex string.

Key Differences Between Ethereum & Solana Private Keys:
Ethereum: Private keys are 32-byte hex strings (e.g., "0xabc123...xyz").

Solana: Private keys are 64-byte Uint8Array (not hex!) and need to be handled differently.

----------------------------------------------------------------------------------------

Initially, we used Infura for Ethereum RPC and public Solana RPC endpoints. However, we later developed our own API to handle blockchain interactions more securely and flexibly. Our API acts as a middleware between the browser extension and the blockchain networks (Ethereum & Solana). Instead of directly embedding RPC endpoints in the extension, our API handles transaction requests and key management securely.

For Ethereum & Solana Transactions:

The extension doesn't connect directly to Infura or Solana RPC. Instead, it makes API calls to our own backend (server.js), which then communicates with the blockchain.

This enhances security and allows future upgrades without modifying the frontend extension.

For Wallet Management:

The API helps in wallet creation and authentication. Instead of exposing private keys in the frontend, they can be securely stored or encrypted.
